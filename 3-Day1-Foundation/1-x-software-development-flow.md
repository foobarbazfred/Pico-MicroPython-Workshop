# マイコンプログラムの開発の流れ
## 各種周辺機器を接続するマイコンプログラムの作り方（設計・実装・テスト）
1. 構造設計
   1. アプリの目的を明確化、要件を整理 
   2. 目的に応じて使うセンサを選択
   3. 出力手段を決定(液晶パネル、LED、音、音声、アクチュエータやサーボモータ、IoT PFへの送信)
   4. 周辺IOや入出力ピンが要件を満たすか確認(デバイスの電圧も確認)
   5. 測定データ判断方法を決定
2. プログラム設計
   1. センサの接続方法(UART/I2C/SPI等)を確認、センサ用のドライバを確認
   2. 出力手段の接続方法を確認
   3. ピン配置を決定(pinごとに用途が決まっています)
   4. 蓄積・判断方法（手段やアルゴリズム）を決定
3. 実装
   1. センサのドライバを入手、単体で動かして正常に値が取れることを確認
   2. 出力手段がデバイスの場合、ドライバを入手、単体で動かして出力されることを確認
   3. 出力手段がIoT PFへのデータ送信の場合、認証トークンを取得して、値がPOSTできることを確認
   4. 入出力デバイスを制御できるように初期化処理を実装(setupの部分)
   5. 蓄積・判断のアルゴリズムを実装。永続化が必要な場合、SD-CARD等の利用を検討する
   6. 入力・判断・出力のメインループを実装(loopの部分)
4. テスト
   1. アプリが正常に動作するかテストします。
   2. センサの最大値、最小値、中間値等で正しく動作するかテストします。センサと接続できない場合やセンサから異常値が返る場合にもエラー処理できているか確認します。
   3. メモリサイズや速度が問題になる場合があります。扱うべきデータが大きすぎて配列が確保できない場合、SD-CARDを一時記憶領域として使う方法や、PSRAM搭載のボードに変更する対応が必要になる場合があります。速度が不足している場合、MicroPython言語のままでチューニングして速度改善する、あるいは、プログラミング言語自体の見直しを行います
   4. 長期運用の場合、プログラムのメモリ枯渇が起きないか、バッファフルにならないかを確認
   5. Exception等、プログラム自体が異常に陥っても、再起動後、正常動作するかを確認
   6. ネットワーク経由の場合ネットワーク断による異常動作が発生しないかを確認します
